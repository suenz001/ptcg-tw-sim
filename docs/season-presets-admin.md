# 預設牌組與錦標賽賽季管理

## 部署與資料保留

v6.602 提供預設牌組管理；v6.603 提供賽季功能。伺服器補丁 v1.76、admin v1.91 與同版 server-engine 必須一起更新。站長自行先執行 `update-tournament.bat`，再執行 `redeploy-oracle.bat`；AI 不執行正式部署。GitHub Pages 沒有 Oracle API，僅使用編譯時的內建牌組，不能用它驗證正式後台管理。

上線前請保留現有 MongoDB 備份。新資料只寫入獨立集合 `managedPresetDecks` 的 `catalog` 文件，以及 `tournamentSeasonState` 的 `state` 文件；不清空帳號、玩家牌組、報名牌表、對戰狀態、賽事歸檔或名人堂。兩集合首次讀取才初始化，重新部署不覆寫既有管理結果。回退程式時保留這兩集合，不以刪除集合當成重設方式。

## 預設牌組

admin「預設牌組」分頁可貼上名稱與文字牌表，預覽精確卡名、卡包、卡號及張數，確認後新增。支援「張數 卡名 #卡片ID」、「張數 卡名 卡包 卡號」，以及能唯一識別的卡名。未知或有多種版本的卡名須補上精確卡號；伺服器會依當前卡池政策及中央牌組驗證器重新驗證，不自動替換版本。

下架與復原都需確認。下架只移出官方供應清單，玩家已複製的牌組、已報名或進行中的牌表不變。可以下架全部牌組，不會因清單為空而恢復內建牌組。若目前選取項目被下架，玩家會收到重選提示。

編輯器與對戰選單只在相關頁面載入，重新回到前景時有限節流更新。有成功快照而 API 暫時失敗時，保留快照並提示可能過期；沒有快照則提示載入失敗並可重試。同名現役預組不覆寫；多人同時編輯衝突會要求重新載入。

## 賽季

admin「賽事」分頁的賽季管理可立即開始下一季，或指定未來日期於台灣時間 00:00 生效。提交前會列出舊季、新季與生效時間供確認。一次只有一筆待執行排程，可改期或取消；有排程時須先取消，才能立即換季。伺服器停機錯過日期，恢復後依原定日期補執行一次。

初始為 2026 年第一季，既有歸檔全部保留。同年每次換季增加序號，不限四季；生效年度不同則從該年第一季開始。跨年本身不會自動換季。已生效時間線不可回溯修改，上限 500 季，達上限時明確拒絕新增，需先維護資料結構。

玩家「排行」可選已生效季別，六種榜單分季統計，空的新季不沿用舊季數字。個人分頁維持生涯累計。跨季賽事依歸檔 `startedAt` 歸屬；缺少有效開賽時間時依 `createdAt`，兩者均缺失或異常時固定歸初季，不依會變動的結賽時間。舊季賽事跨季才完賽時仍會補入舊季，因此舊季不是換季瞬間永久凍結。社群主辦榜依賽事建立時間，維持原先計次範圍。

每季排行最多快取 60 秒、最多八份，並合併同季查詢；歸檔新增、刪除及管理換季會失效快取。控制文件一般讀取最多快取五秒，排程到期不等待快取過期。多視窗衝突或年度跨越會拒絕舊確認，要求重新預覽。

## 查詢效能與驗收限制

本機 MongoDB 7.0.14，以 15,006 筆合成歸檔（含缺失、陣列及無限日期）驗證真正 `seasonArchivesFor`：三季合併每筆剛好一次，尚未換季的初始查詢與全歷史筆數一致。後續季以兩個日期索引範圍查詢，第二季回 5,001 筆、檢視 10,001 筆；第三季回 5,001 筆、檢視 10,002 筆。此為本機合成資料量測，不代表正式站延遲。

切過季以後，初季缺失時間的負向條件仍可能全掃歸檔（本機檢視 15,006 筆）；60 秒快取降低頻率，沒有消除全掃。資料量顯著增加時應另規劃安全的時間欄位清理或持久季別遷移，不在本版直接改寫歷史。

管理確認與排行手機/桌機互動採隔離瀏覽器測試，資料庫亦為本機合成資料。未向正式站建立測試帳號、牌組或賽事；正式資料的初季逐榜對照仍應由站長部署後確認。
